## 1. 目的与范围

### 1.1 目的

S5 是用户使用 Factory 的唯一界面。它让用户在任何时刻都能看清：当前项目与阶段、已有产物、已批准的结论、未决的不确定性、需要确认的事项、下一步可执行的动作、动作会影响的 DHIS2 环境，以及最终会得到的交付物（总体 SRS 18 章引言）。S5 不持有任何业务状态，所有状态与动作合法性以 S1 为准。本文档是 S5 开发组的唯一需求输入。

### 1.2 范围内

1. 应用框架、导航、国际化、无障碍、帮助与实例教程；
2. 操作者标识（MVP 替代登录）与登录、会话、账号与权限界面；
3. 装机引导、Dashboard、项目列表与创建向导；
4. 项目工作台：阶段流程、各阶段视图、对象详情、Question 整页问卷、Gate 审批、阶段内对话；
5. 人工编写（结构化表格与 JSON 编辑器）；
6. 产物审核（按媒体类型预览与下载）、元数据审核、对象依赖图、决策页、接口文档审核、开发包；
7. Deployment Run、部署控制台与提交后结果；
8. Change Request、审计、通知中心；
9. 环境管理、Governance（模型、提供方、策略、提示词、用量与预算）、系统设置；
10. 跨项目待审批收件箱与实时更新（SSE）。

### 1.3 范围外

| 不负责 | 说明 |
| --- | --- |
| 任何业务判定（动作是否合法、Gate 是否满足、状态迁移） | 由 S1 判定（总体 SRS FR-UI-009） |
| 直接访问数据库、DHIS2、模型提供方或 S1 以外的子系统 | 总体 SRS C-01；接口文档也不提供“试运行” |
| 持有 DHIS2 凭证、模型密钥的值 | 只在录入的那一次经 HTTPS 请求体透传给 S1，不显示、不缓存、不落任何浏览器存储（总体 SRS FR-SEC-006、FR-SEC-007） |
| 页面预览 | S1 不提供页面预览端点，界面不画一个打不开的页签 |
| 角色编辑器 | 角色是 S1 的内置表，界面只读展示角色及其动作清单 |
| 产物清除动作 | 只呈现 S1 的清除结果（记录保留、字节已清除），本控制台不提供清除入口 |

## 2. 领域概念与定义

| 概念 | 定义 |
| --- | --- |
| 操作者名称 | MVP 中由用户在界面中填写、随每个改变状态的请求以 `X-Operator` 发送的名称（D-16） |
| 允许动作 | S1 `allowed-actions` 返回的可执行动作及不可用原因；按钮可用性的唯一依据 |
| 工作台 | 项目内按阶段组织的主界面：横向阶段流程 + 五个一级分节 + 分节内子页签（总体 SRS 18.2） |
| 部署控制台 | 单个 Deployment Run 的执行视图（总体 SRS 18.3） |
| 事件序号 | SSE 事件在工作流内单调递增的序号，用于断线补发 |
| 整页问卷 | 一个阶段全部 `OPEN` 问题的单页作答界面：一次提交，服务端最多 resume 一次（UI-Q-004、CP-Q-005） |

### 2.1 取值词汇表

服务端以记号发出的状态、角色与类别，每一个都必须在两种语言里有一个词。完整词表与英文列见 `requirements/S5M_移动优先前端_SRS.md` §2.1（两端共用同一张表）；桌面端由 `src/lib/labels.ts` 与 `StatusBadge` 读取本仓库 `src/i18n` 中的词，缺词、词就是记号本身由 `src/lib/vocabulary.test.ts` 判红。查不到的记号**原样显示**，不猜也不留空。

问卷的单选/多选取值 `QuestionView.answerMode`（`SINGLE` / `MULTIPLE`）在界面上读作「单选」「可多选」，推荐建议 `SuggestionView.recommended` 读作「推荐」（UI-Q-004）。

## 3. 功能需求

### 3.1 应用框架（UI-APP）

- **UI-APP-001**【直引】（18.5）界面采用 DHIS2 设计系统 `@dhis2/ui`。
- **UI-APP-002**【直引】（NFR-UX-003、18.5）界面语言至少支持简体中文与英文，全部文案通过翻译资源管理；用户可切换语言，请求携带 `Accept-Language`。文案中的变量必须使用所选用翻译库的插值语法（i18next 是双花括号），并由机器校验：单花括号占位符会原样显示在界面上，两种语言的资源都要检查。
- **UI-APP-003**【直引】（NFR-UX-001）满足 WCAG 2.1 AA。
- **UI-APP-004**【直引】（NFR-UX-002）支持 Chrome、Edge、Firefox、Safari 的最新两个主版本；最小视口宽度 1280 像素。
- **UI-APP-005**【新增】S1 的 API 基址在部署时通过运行时配置文件提供，不在构建时写死。理由：同一镜像部署到不同环境。
- **UI-APP-006**【直引】（FR-WF-006）服务器状态只经 TanStack Query 从 S1 获取；本地状态管理（Zustand）只保存界面状态（选中项、面板布局、筛选条件），禁止保存或推断业务状态。
- **UI-APP-007**【新增】所有 API 客户端代码由 S1 发布的 OpenAPI 生成；数据校验使用由同一 OpenAPI 生成的 Zod 模型。理由：与 S1 契约保持一致，减少手写接口代码。
- **UI-APP-008**【新增】S5 与 S1 经同一反向代理同域部署（静态资源与 `/api/v1` 同源）。理由：避免跨域请求与 SSE 跨域问题。
- **UI-APP-009**【新增】提供页内帮助抽屉与一篇可走通的实例教程（`/help/tutorial`）；帮助回答“这一页是什么”，教程回答“下一步按什么、会得到什么”。两者不得与本文档或界面实际按钮名称矛盾。

### 3.2 操作者标识（UI-OP）

- **UI-OP-001**【新增】（D-16）首次使用时要求填写操作者名称；名称保存在浏览器本地，页面顶栏始终显示，可随时修改。理由：MVP 不含登录，审计与审批仍需记录操作人。
- **UI-OP-002**【新增】（CP-API-002）未启用认证时，未设置操作者名称则所有改变状态的操作不可用并提示先填写。理由：S1 对缺少 `X-Operator` 的请求返回 400（CP-API-002）；启用认证后该前提不成立，见 UI-OP-004。
- **UI-OP-003**【新增】所有改变状态的请求自动附加 `X-Operator`。
- **UI-OP-004**【新增】（CP-IAM-002、FR-SEC-001）S1 启用认证（`authMode != off`）时，操作人身份来自会话：顶栏显示账号的显示名、角色与会话到期时间，不再要求填写姓名，也不得因未填写姓名而禁用任何动作；已经打开的姓名填写框必须在会话到达后关闭。理由：S1 用会话主体覆盖 `X-Operator`（CP-IAM-001），此时再问姓名既不生效又把使用者挡在功能之外。
- **UI-OP-005**【新增】（CP-API-002）`X-Operator` 的取值超出 ISO-8859-1 时，界面必须先 `encodeURIComponent` 再发送。理由：HTTP header 值被 Fetch 标准限制在 Latin-1，Chromium 遇到中文姓名在 `Headers.set` 就抛 `TypeError`，请求根本不发出——操作者看到的是「无法连接服务器，请检查网络」，而坏掉的只是他自己输入的名字。装得下的姓名（含 `Renée` 这类 Latin-1 名字）按原样发送，S1 两侧都能还原（契约 1.6.0）。

### 3.3 请求、错误与幂等（UI-REQ）

- **UI-REQ-001**【新增】每个创建类与执行类用户动作生成一个幂等键（UUID），同一动作的自动或手动重试复用该键。理由：S1 以幂等键防止重复执行（CP-API-003）。“同一动作”的边界由**这次动作要做什么**决定，不是由端点决定：intent 必须带上请求体的摘要——只按“端点 + 目标 id”算的话，给同一个人授第二个角色会与第一次同键，而 S1 对“同一个键、不同的请求体”回答 422 `IDEMPOTENCY_CONFLICT`，第二个角色就授不出去。键是给重试用的：内容相同才重放第一次的响应；被 S1 明确答复拒绝的请求释放键，网络失败与 `REQUEST_IN_PROGRESS` 保留键。
- **UI-REQ-002**【调整】（19.2.1）错误以 `errorCode` 映射为本地化提示；同时显示 `correlationId` 供排查；`retryable = true` 的错误提供“重试”操作。`404 NOT_FOUND` 且 `details.reason = NOT_GENERATED` 是可解释的空态：页面就地说明“由哪个阶段生成”并给跳转（CP-UI-022）；草稿读取把这种回答解析为“暂无草稿”，不把它上抛成全局错误。
- **UI-REQ-003**【新增】收到 409 时刷新相关资源与 `allowed-actions` 后再提示原因；收到 `APPROVAL_INVALIDATED` 时刷新 Gate 页面并提示“内容已变化，请重新审阅”。理由：状态已在服务端变化。
- **UI-REQ-004**【新增】COMMIT 请求网络失败后，界面不得自动重新提交；必须显示“结果待确认”，由用户以同一幂等键重试（S1 会先查询执行状态，CP-GATE-018）。理由：总体 SRS AC-EXE-05。

### 3.4 实时更新（UI-RT）

- **UI-RT-001**【直引】（FR-UI-010）阶段、Agent、校验、执行状态通过 SSE 实时刷新；断线重连时携带最后收到的事件序号，由 S1 补发。
- **UI-RT-002**【调整】（C-02）事件只用于触发刷新：收到事件后使相关查询失效并重新获取，不直接以事件 payload 作为状态。
- **UI-RT-003**【新增】收到 `stream.reset` 时对当前项目根下的全部查询（阶段、审批、部署运行、产物、问题、执行）做全量刷新。理由：CP-EVT-004。
- **UI-RT-004**【新增】显示 Agent 与执行的进度（`agent.progress`、`execution.progress`）：当前步骤、完成比例（如有）、已产生的 Patch 与 Question 数量。理由：进度回调是 Agent 与执行实时状态的唯一来源。
- **UI-RT-005**【新增】连接断开超过 10 秒时显示离线提示，恢复后自动补齐。理由：用户需知道界面可能不是最新。

- **UI-IA-001b**【调整】治理页一条分节一条地址（`/governance/models`、`providers`、`policy`、`prompts`、`cost`），`/governance` 只做跳转，页面标题跟着分节走（`治理 · 模型`）。「站内链接必须命中路由表」由 `src/features/navIntegrity.test.tsx` 守住：它把 `routes.tsx` 的路由表读出来，再扫源码里所有 `Link to` / `navigate(` / `router.push(` 的字面量（模板的 `${…}` 算一段，拼接的尾段补一段），断言每条都命中；UI-REV-007 那个 404 就是这么找出来的，钉成测试才不会再来一次。

### 3.6 Dashboard 与项目（UI-PRJ）

- **UI-PRJ-001**【调整】（18.1）Dashboard 显示：全部项目（含里程碑与工作流状态）、待审批 Gate、最近执行、未读通知，以及装机清单中仍未完成的第一步（只列缺模型/缺环境/缺项目，不催“跑通流水线”）。
- **UI-PRJ-002**【调整】（2.5～2.7、CP-PRJ-001）新建项目向导依次收集：名称与描述、负责人名称、交付模式（A / B）、项目类型（Greenfield / Brownfield）、目标版本约束、默认语言与翻译语言、目标环境（至少一个非 PRODUCTION；指定设计基准环境与晋级顺序）；提交前显示汇总。负责人一项默认填入当前身份（有会话时为账号显示名，无会话时为已填写的操作人姓名，UI-OP-004），并允许改成他人——填进去的值就是最终值，不得被本地操作人姓名悄悄顶掉。
- **UI-PRJ-003**【直引】（AC-WF-01）新建项目后显示全部阶段、当前阶段与下一步需要提供的信息；模式 A 的 PAGE_DESIGN 与 HANDOFF 显示为 SKIPPED。
- **UI-PRJ-004**【新增】项目设置页提供：目标环境增删与排序、更换设计基准环境（提示将使 DISCOVERY 及其后阶段失效，CP-PRJ-003）、交付模式升级（A → B）、通知渠道、审批提醒时长、归档、删除（仅已归档，需输入确认词）、导出与导入。理由：S1 项目管理能力的界面；可用性仍只来自 `allowed-actions`。

### 3.7 工作台（UI-WB）

- **UI-WB-001**【调整】（18.2）工作台采用**横向阶段流程 + 五个一级分节**的单列布局，页面内容占满宽度；不再有第二条左侧阶段栏与常驻右侧检查器。阶段流程是页内导航，当前阶段以 `aria-current="step"` 标出。
- **UI-WB-002**【调整】（FR-UI-001）阶段流程中每个阶段显示：阶段状态（与 S1 状态一致，含 MANUAL_CHECK）、待答问题数，以及 HIGH 未答或阻断问题的警示标记。阶段内容、运行记录与产物由阶段页和结果页显示；Deployment Run 的步骤在 Deployments 中按环境显示。

### 3.9 Question（UI-Q）

- **UI-Q-001**【直引】（FR-UI-003）结构化展示 Question：问题、影响对象、严重程度、建议及其理由、是否改变 UID、需重新生成的产物、推荐标记；支持选择建议或填写自定义回答。
- **UI-Q-002**【新增】未回答的 HIGH 级 Question 在阶段流程条与审批收件箱醒目提示，并说明其阻止批准；阻断（`blocking`）问题未答完时问卷不能提交。理由：CP-Q-006。
- **UI-Q-003**【新增】回答提交后不可编辑：问卷只渲染 `OPEN` 问题，提交后该题离开问卷；回答人与时间由 S1 记录，界面不提供修改入口。理由：CP-Q-007。
- **UI-Q-004**【新增】（CP-Q-005、S5IF-FLD08）**整页问卷**：一个阶段页把该阶段全部 `OPEN` 问题放在同一张卡片里作答，而不是逐题提交。

  1. 一屏列出全部问题（HIGH 优先），逐题显示严重程度、单选/多选标记、阻断/选填标记与影响对象；每条建议显示文本、推荐标记、理由、是否改变 UID、需重新生成的产物。
  2. `QuestionView.answerMode = SINGLE` 用单选按钮，`MULTIPLE` 用复选框；每题都提供「其他」自由填写。单选时「其他」与建议互斥；多选时自定义文本可与所选建议一并提交。
  3. 阻断问题没有任何有效答案（没选建议，或只选了「其他」且文本为空）时，该题标红且整页提交按钮不可用；至少有一条有效答案才能提交。服务端仍会独立校验，界面校验只是把错误提前。
  4. 整份问卷一次 `POST /api/v1/questions/answers` 提交（`AnswerQuestionsBody.answers[]`，1～200 条；幂等键 intent 含请求体摘要）。S1 在一个事务里记录全部答案并**最多 resume 一次**，界面不逐题发请求、不在第一题之后就让 Agent 继续跑。
  5. 响应 `QuestionnaireAnswerView.questions` 是 resume 后仍在开放的问题；界面使问题、阶段、审批与允许动作查询失效，在同一张卡片里渲染下一轮，并提示新问题数或「已全部回答」。第二轮问题不需要刷新页面，也不靠再猜一次读取。
  6. 运行与作答携带 `Accept-Language`，S1 据此让新一轮问题使用当前界面语言；已存在问题文本不因切换语言而改写。
  7. 问卷草稿只保存在组件状态，离开页面即丢弃，不写入任何浏览器存储。

- **UI-ADM-005**【新增】（AI-COST-001～003、CP-UI-006）用量与预算：用量按项目查询，分组维度取自响应给出的维度列表（默认按阶段、Agent、模型），界面不写死维度；预算按项目作用域查看与设置（留空表示沿用平台默认），可设上限与多级告警阈值及币种；预算状态（未设置、正常、告警、超限）按 S1 返回的值原样呈现，界面不得用本地数字重新判定；`limit` 置空即清除该项目的上限。
- **UI-ADM-006**【新增】（S5IF-GOV20）提供方「测试连接」：提供方表格每行一个按钮，调用 `POST /api/v1/governance/providers/{name}/test-connection`，按行显示 `ProviderHealthView.healthy` 与服务端原文 `detail`（地址不可达、密钥被拒、超时等）。每次按下生成新的幂等键，不复用上一次的回答；探测只读供应商可达性，不产生一次模型调用，也不因结果改写登记行。理由：`model endpoint unreachable: ConnectError` 无法区分“地址没填、密钥被拒、模型太慢”，而这个探测把三种问题拆开。

### 3.16 登录、会话与权限管理（UI-AUTH，本期交付）

- **UI-AUTH-001**【新增】（CP-IAM-002、FR-SEC-001、FR-SEC-005）当 S1 启用认证（`authMode != off`）时提供登录与登出：本地账号口令与组织单点登录两种方式，会话查看（账号、显示名、角色、到期时间）。会话只由 HttpOnly Cookie 承载，由浏览器自行发送，界面与本地存储不得保存任何令牌明文；以 Cookie 会话发起的改变状态请求必须携带 CSRF 双提交头。`authMode = off` 时不出现登录界面，按 3.2 的操作人姓名方式工作。理由：S1 的会话 Cookie 带 `Secure` 属性，只有 HTTPS 来源才拿得到会话。
  同一处必须提供**修改自己的口令**（`POST /api/v1/users/{user_id}/password`，本人调用不需要 `user.manage`，CP-IAM-005）：标记 `mustChangePassword` 为真时，顶栏下方必须出一条提示把这件事说清楚——CP-IAM-005 ③ 裁决它是**报告位**（服务端不因此拦截任何调用），因此“这个标记意味着什么”只有界面能讲。口令格 `type="password"` + `autocomplete="new-password"`，两次输入一致才可提交，值不进任何浏览器存储、成功失败都立即清除，界面永不显示其原文。S1 在写入口令时吊销该账号全部会话（CP-IAM-004），**包括正在用的这一条**，因此必须在提交前说明“改完要重新登录”，成功后走与 401 相同的落定路径（清 CSRF 值、丢弃会话缓存、置“会话已过点”）。会话中途过点的处理与移动端 UM-NET-009 同一条规则：只提示一次。
- **UI-AUTH-002**【新增】（CP-API-002、FR-SEC-005）会话失效要按“会话没了”来反应，而不是按“这次调用错了”：401 只公告一次并弹出登录门，不得让每个在途请求各自弹一条错误；CSRF 校验失败（403）只拒绝本次操作并说明原因，绝不静默地重新登录。
- **UI-AUTH-003**【新增】（CP-IAM-002、FR-SEC-002、FR-SEC-003、FR-SEC-004）权限管理界面：用户（列表、新建、启用停用、设置口令——**登录名 `subject` 与显示名 `displayName` 是两个字段**：新建时登录名必填、显示名单独填写，列表里两列都显示，前者是认证与审计里用的那串，后者是给人看的那串，不得互相代替）、角色及其动作清单（只读）、项目成员（加入、移除、项目内角色）、受限与 PHI/PII 产物的读取授权、生产豁免。凭证类字段一律只接受 Secret 引用（UI-ADM-002）。写操作是否可用一律来自 `allowed-actions`（CP-UI-023），不可用时置灰并显示原因，不发试探性请求。**账号建好之后仍然要能管**：显示名与邮箱在同一页可改（`PATCH /users/{id}`），停用/启用也是——S1 没有删除端点，停用就是唯一的退场方式；登录名不提供修改入口，它是审计与审批记录里的那串。新建时的 `mustChangePassword` 由操作者勾选（默认勾上），不得由界面写死。被五次失败锁定的账号必须在用户列表里显示 `locked`（`status` 仍是 ACTIVE，所以只改颜色不算说明）。

### 3.17 装机引导（UI-SET）

一次全新装机到第一次成功提交之间，操作者要按顺序做完若干件互相依赖的事；此前界面把这条路拆散在四个页面里，而且**零数据时空白表格看起来像坏了**。本节把这条路显式化。总体 SRS 1.4 排除的是“面向非技术业务人员的引导式体验”，本节面向**实施工程师**，不构成对该范围的改变。

- **UI-SET-001**【调整】（S5IF-SET01、FR-UI-009）提供“开始使用”视图，按 `模型与提供方 → DHIS2 环境 → 新建项目 → 跑通流水线` 的顺序呈现一条**就绪清单**，并为**一步一屏**：一次只展开当前这一步，屏内直接给完成它所需的表单，而不是只给一个跳转。步骤条本身是页内导航，当前一步以 `aria-current="step"` 标出；操作者点别的步骤不会离开本页。每一项的状态只由 `GET /api/v1/setup` 的事实与 `allowed-actions` 的可用性推导；S5 不得自行推断“还缺什么”（UI-BR-02）。每一项给出：当前事实、未完成时会发生什么、以及完成它的入口。
- **UI-SET-002**【调整】（S5IF-SET01、UI-APP-002）配置本身出错时（`configuration.problems` 非空）必须在清单顶部以可复制的原文显示，并说明这些句子指向 `.deploy/env` 里的变量名、不含任何取值；子系统跑在替身上（`providers` 含 `fake`）必须显式标注“结果不可交付”，不得与真实接入同样显示为就绪。**能力接入不占清单步骤**：`providers` 是 S2/S3/S4 的真身与替身选择，属于部署配置（`provider_mode`），浏览器里没有任何控件能改变它；清单末尾只用一张事实卡报告它，不提供表单——给一个能填的表单就是骗人。
- **UI-SET-003**【调整】（UI-ADM-001、S5IF-ENV08、S5IF-SEC01）环境已登记但从未通过连接测试（`environments.neverTested`）时，该项显示为“待测试”而不是“已完成”。该步的表单就地完成登记：接口地址、类别、认证方式、各凭证范围，凭证一栏用 UI-ADM-002 的一次性录入控件填入用户名/口令或 API key，也保留手填 `env://…` 的路径；保存后本页重新读取清单，该项变为“待测试”，并给出环境页入口——连接测试在环境页/环境详情执行，结果不在引导页伪造。
- **UI-SET-004**【调整】（UI-PRJ-002、UI-BR-01）新建项目向导与本页共用同一前置事实：环境清单为空时向导不得出现“点了没反应”的步骤，必须显示原因与去登记环境的入口；“新建项目”按钮的可用性只来自平台作用域 `allowed-actions` 的 `project.create`。项目向导与工作台是页面而不是对话框，因此这一步保留跳转——引导不得为了“留在本页”而把浏览器历史弄成假的东西。
- **UI-SET-005**【调整】（S5IF-GOV04、S5IF-GOV05、S5IF-GOV06、S5IF-GOV07、UI-ADM-003）引导清单是**四步**：模型与提供方第一、环境第二、项目第三、跑通流水线第四——顺序按「没有它就什么都跑不动」排，不按登记对象的种类排；每一步都跳到 UI-IA-001 的分节地址，不再统一丢到治理页顶部。「能力接入」不再是其中一步：`GET /setup` 的 `providers` 由服务器自己的 `FACTORY_PROVIDER_MODE` 决定，浏览器里没有任何控件改得动它，列成清单项等于布置一个完不成的任务，而一条可以忽略的清单项会教会人忽略整张清单。这句话现在写在清单末尾的一张事实卡上，替身在跑时点名是哪一项，并原样附上服务端那句 `能力: 状态`。
- **UI-SET-005a**【新增】（S5IF-GOV06、UI-ADM-003）已登记的模型必须能在界面上改。表单收一个「已存行或空」的入参：为空是登记（`POST`，整行必给），非空是编辑（`PATCH /governance/models/{ref}`，**只发改动过的字段**）；一个字段都没动时保存按钮不可用，因为服务端把空差量读成 422。编辑态里提供方与模型标识锁死——两者拼成这一行的 `ref`，改它们等于登记另一行。差量里**永不出现** `endpoint` 与 `apiKeySecretRef`：登记路径会把没给的列写成 NULL，静默清掉模型级覆盖，而读路径又会把 NULL 回填成提供方的地址，界面再把它当覆盖发回去，覆盖就再也撤不掉。编辑保存后列表必须重新读到那一行。启停开关与编辑表单共用同一个动作 `governance.model.enable`（S1 只给了一个动词），两处门禁因此同源。
- **UI-SET-005b**【调整】模型这一步同时打开它依赖的两件事：登记提供方（UI-SET-006）与登记模型（`POST /governance/models`、`PATCH /governance/models/{ref}`），因为模型必须挂在已存在的提供方之下，只给一个入口等于让操作者用一次 422 自己发现顺序。引导中把“没有任何可用模型”与“阶段运行会失败”连起来说明；无治理读取权时该节显示为“无权查看”，不得显示为 0。两个入口的可用性同样只来自 `allowed-actions`（`governance.provider.register`、`governance.model.register`），不可用时给出 S1 的原因。
- **UI-SET-006**【新增】（S5IF-GOV07、UI-ADM-002、UI-ADM-003）模型提供方登记内嵌**厂商目录**：选项来自 `GET /api/v1/governance/provider-catalogue`，界面不写死厂商名。每条给出显示名、接口地址、线协议、常用模型名与建议的凭证引用名；地址与模型名都可改成自由输入（私有网关、微调与改名的部署是常态，下拉框不能比事实小）。目录只列 OpenAI 兼容协议的厂商，选中项的地址与协议一并带出；`adapter` 在本版本只有一个实现（`openai_compat`，S3 的 `provider_for()` 不看该字段），因此它显示为固定值而不是选项。目录条目不代表已验证连通（AI-CAT-001），连通与否由 UI-ADM-006 的连接测试与调用结果说明。
- **UI-APPR-001**【新增】（S5IF-FLD03、UI-PRJ-001、UI-GATE-001）审批人有自己的顶层入口：左侧主导航「待审批」→ `/approvals`，跨项目列出 `GET /gates?status=WAITING_APPROVAL`，一行一个节点，写清所属项目、这个节点关掉哪一段活（用阶段那七个词，不发明第二套词汇）、目标环境、已批／需要几次、还没处理的警告数、高优先级未答问题数。`只看等我批的` 用服务端的 `mine`，`按项目筛选` 用服务端的 `projectId`，分页与「已列出 x / 共 N」遵守 S5IF-G04。这一页不放批准也不放驳回——决定只在审批页那一屏发生，`CP-GATE-012` 的角色分离不能被一个列表页绕开。
- UI-REV-007 的完整要求见 3.12（决策页与登记表「决策」列），此处不重复定义。
- **UI-IA-001a / UI-IA-001b**【调整】见 3.5。
